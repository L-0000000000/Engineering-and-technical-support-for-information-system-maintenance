Данный текст, работа не являются частью общественного резонанса на нейрослоп, при создании контента были взаимодействованы: кора головного мозга, периферическая нервная система и.т.д!

1.Git - распределённая система управления версиями "DVCS", предназначенная для отслеживания изменений в исходном коде в процессе разработки ПО.

Для чего:
С точки зрения архитектуры, Git не просто фиксирует разницу между файлами (diff), а оперирует снимками (snapshots) файловой системы. Это обеспечивает высокую скорость работы, надежность данных и полную независимость от центрального сервера: каждый разработчик имеет локальную копию всей истории репозитория.

Ключевые функции:
Атомарные коммиты - фиксация логически завершенных изменений с сохранением метаданных.
Изолированное ветвление - создание дешёвых и быстрых веток, исправления багов без риска дестабилизировать основной релизный цикл.
Параллельная разработка и слияние - инструменты для автоматического и ручного разрешения конфликтов.
Аудит и реверс-инжиниринг - возможность точечного отката, перемещения по истории, поиска авторов багов.

2.В чём разница между централизованными и распределёнными системами контроля версий?

Централизованная система - у вас есть один главный блокнот, который лежит в сейфе, в офисе.
Распределённая - у каждого из вас есть точная копия всего блокнота со всей историей правок с самого первого дня.

Наглядная разница: один общий vs каждому по копии.

3.Что такое репозиторий в Git?

Репозиторий в Git — это умная папка с твоим проектом, внутри которой прячутся скрытые файлы Git. Они следят за проектом, регистрируют любые изменения и поэтапно сохраняют их в историю по твоей команде.
(в папке находятся: сам код, скрытая директория .git, историю всех изменений, все созданные ветки)
